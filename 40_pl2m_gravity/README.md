## 1. 강의 39 에서 미뤄 둔 것

### 이번 강의의 결과

- 팔을 앞으로 뻗은 채 중력 보상을 3초마다 켰다 껐다 함. 잘 보이도록 팔의 게인을 1/10 로 낮춘 시연임.
- 보상을 끄면 팔이 13.6° 처지고, 켜면 0.3° 안으로 돌아옴.

### 강의 39 에서 한 것

- 강의 39 는 팔의 동작만 확인하려고 팔 링크의 중력을 꺼 두었음.
- 원본 MuJoCo 설정은 중력을 그대로 두고, 관절이 팔 무게만큼의 토크를 더 내게 함 (`bias_compensation: true`).
- 이번 강의는 중력을 다시 켜고, 중력이 무엇을 바꾸는지 잰 다음, 원본과 같은 방법으로 보상함.

### 세 가지 처리

- 구동만: 팔이 처져야 구동이 힘을 냄. 처짐이 남음.
- 구동 + 중력 보상: 필요한 힘을 미리 더함. 처지지 않고, 팔의 무게는 베이스에 그대로 실림.
- 팔 링크의 중력 끔: 처지지 않지만 팔의 무게가 없어짐. 바닥이 받치는 힘이 894 N 에서 776 N 으로 줄어듦.

### 다루는 순서

| 절 | 질문 |
|---|---|
| 2 | 중력을 버티는 데 관절마다 힘이 얼마나 드나 |
| 3 · 4 | 구동만으로 버티면 팔이 얼마나 처지나 |
| 5 · 6 | 중력 보상은 어떻게 넣고, 무엇을 틀리기 쉬운가 |

| 8 · 9 | 움직일 때와 팔이 약할 때는 어떤가 |

| 칸 | 뜻 |
|---|---|
| 0 ~ 2 | 뿌리가 받는 힘 (x, y, z) |
| 3 ~ 5 | 뿌리가 받는 모멘트 (x, y, z 축 둘레) |

- PL-2M 은 바닥에 고정되지 않은 로봇이라 앞에 뿌리 6칸이 붙음. 바닥에 고정된 로봇팔은 관절 값만 나옴.
- 뿌리 위쪽 힘 894.2 N 은 로봇 전체의 무게임 (91.15 kg × 9.81).
- 뿌리에는 모터가 없음. 뿌리 6칸은 보상할 수 없고, 바퀴와 캐스터를 거쳐 바닥이 받침 (7절).

### 코드: 값 읽기

```python
self.physics = omni.physics.tensors.create_simulation_view("numpy")
self.robot = self.physics.create_articulation_view(ROOT)
self.names = list(self.robot.shared_metatype.dof_names)
self.dofs = np.array([self.names.index(name) for name in joints])
# 바닥에 고정되지 않은 로봇은 앞 6칸이 뿌리(힘 3 + 모멘트 3)이고, 관절은 그 뒤에 온다
self.shift = (0 if self.robot.shared_metatype.fixed_base else 6) if shift is None else shift
```

- `ROOT` 는 관절체(Articulation)의 뿌리 `/World/pl2m/base_footprint` 임. Play 뒤에 만들어야 함.
- 값은 `self.robot.get_gravity_compensation_forces()` 로 읽음. 관절의 순서는 `dof_names` 로 확인함. 왼팔과 오른팔이 번갈아 나옴.

### 로봇의 무게가 91.15 kg 인 이유

- URDF 에 적힌 질량을 모두 더하면 90.15 kg 임. PhysX 의 값은 그보다 1.00 kg 많음.
- URDF 에서 질량이 없는 `base_footprint` 링크에 1.0 kg 이 들어가 있었음.

### 그림으로

- 구동만으로는 손이 5 ~ 16 mm 처짐. 팔을 멀리 뻗을수록 큼.
- 게인을 4배로 올리면 1.3 ~ 4.7 mm 로 줄지만 0 이 되지는 않음.
- 보상을 넣으면 0.1 mm 이하임.

### 구동만으로는 왜 처지나

- 위치 구동은 용수철과 같음. 내는 힘이 kp × (목표와의 차이) 라서, 차이가 0 이면 힘도 0 임.
- 무게를 버티는 힘을 내려면 그만큼 처져 있어야 함. 처짐 = 버티는 힘 ÷ kp 로 어림할 수 있음.
- 앞으로 뻗은 자세의 1번 관절: 11.08 N·m ÷ 500 N·m/rad = 0.022 rad = 1.27°. 잰 값은 1.69° 로 더 큼. 이유는 다음 절에서 봄.

### 게인만 올리는 방법

- kp 를 4배(2000)로 올리면 처짐이 1/3 ~ 1/5 로 줄어듦. 없어지지는 않음.
- kv 도 2배(70)로 같이 올렸음. 게인을 어디까지 올릴 수 있는지, 올리면 무엇이 나빠지는지는 재지 않았음.

## 5. 중력 보상

### 생각

- 처지기를 기다리지 않고, 버티는 데 드는 힘을 관절에 미리 더함.
- 드는 힘은 자세만으로 계산됨. 2절에서 읽은 값이 그것임.
- 위치 구동은 그대로 둠. 구동은 남은 작은 오차만 맡음.

### 코드: 물리 스텝마다 더하기

```python
def _on_step(self, dt):
    efforts = np.zeros((self.robot.count, self.robot.max_dofs), dtype=np.float32)
    if self.enabled:
        needed = self.robot.get_gravity_compensation_forces()
        if self.coriolis:                                     # 움직일 때 생기는 힘(코리올리 · 원심력)까지
            needed = needed + self.robot.get_coriolis_and_centrifugal_compensation_forces()
        efforts[:, self.dofs] = needed[:, self.shift + self.dofs]
    self.robot.set_dof_actuation_forces(efforts, self._every)
```

- 자세가 바뀌면 드는 힘도 바뀌므로 물리 스텝마다 다시 읽어 넣음.
- `set_dof_actuation_forces` 로 넣는 힘은 위치 구동이 내는 힘과 따로이고, 둘이 더해짐.
- 팔 관절 14개에만 넣음. 원본도 손가락을 뺀 팔 관절에만 보상함.

### 코드: 스텝마다 부르게 하기

```python
self.enabled, self.coriolis = True, coriolis
self._every = np.arange(self.robot.count)
self._sub = omni.physx.get_physx_interface().subscribe_physics_step_events(self._on_step)
```

- 물리 스텝마다 불리는 이벤트임. 강의 3 의 떨어지는 상자와 `common/sim.py` 의 `Sim` 이 쓰는 것과 같음.
- `enabled` 를 False 로 바꾸면 0 을 넣음. 9절의 시연이 이것으로 보상을 켰다 껐다 함.

### 쓰는 법

```python
prepare_pl2m(stage)                      # 강의 39 의 tune_pl2m 과 같되 팔 링크의 중력을 켜 둠
sim = Sim(app)
sim.play()
sim.run(1.0)
compensation = GravityCompensation()     # Play 뒤에 만든다
```

- 끝낼 때는 `compensation.stop()` 을 부른 뒤 `sim.stop()` 을 부름.
- 결과는 3절 표의 마지막 줄임. 손의 처짐이 0.1 mm 이하가 됨.

### 실수 1: 뿌리 6칸을 건너뛰지 않음

- 26개 값의 앞 20개를 관절 값으로 쓰면, 로봇의 무게 894.2 N 이 관절 하나의 토크로 들어감.

### 실수 2: 중력을 끈 채 보상

- 드는 힘의 계산은 링크의 Disable Gravity 를 반영하지 않음. 강의 39 처럼 중력을 꺼도 같은 값이 나옴.
- 중력이 없는데 보상을 넣으면 팔이 위로 밀림. 1번 관절이 1.54° 올라가고 손이 19 mm 높아졌음.
- 둘 중 하나만 써야 함. 중력을 끄거나, 켜고 보상하거나.

| 운반 | 10.33 N·m | 42.0 × 0.244 = 10.25 |
| 앞으로 뻗기 | 22.57 N·m | 92.1 × 0.244 = 22.47 |
| 뒤로 뻗기 | 20.32 N·m | 84.7 × 0.244 = 20.67 |

- 캐스터는 바퀴 축에서 앞뒤로 0.244 m 떨어져 있음 (URDF 의 값).
- 2절에서 읽은 뿌리 모멘트를 캐스터가 받치고 있음. 따로 잰 두 값이 2 % 안에서 맞음.

### PL-2M 은 무게중심이 바퀴 축 위에 있음

- 팔을 내리면 무게 894.2 N 가운데 893.6 N 이 바퀴 둘에 실림. 캐스터는 거의 받치지 않음.
- 팔을 뻗어 무게중심이 옮겨져야 캐스터가 받침. 앞으로 뻗으면 무게중심이 앞으로 25 mm 나감 (22.57 ÷ 894.2).
- 중력을 끄면 이 변화가 없음. 팔을 뻗어도, 뒤에서 물체를 들어도 베이스는 모름.

### 코드: 저울

```python
@staticmethod
def prepare(stage):
    for link in GROUND_LINKS:                                 # 접촉을 보고하게 한다
        PhysxSchema.PhysxContactReportAPI.Apply(stage.GetPrimAtPath(f"{ROBOT}/{link}")).CreateThresholdAttr(0.0)
    # 가만히 서 있는 로봇은 곧 잠들고(sleep), 잠든 동안에는 접촉 힘이 0 으로 읽힌다. 잠들지 않게 한다
    PhysxSchema.PhysxArticulationAPI.Apply(stage.GetPrimAtPath(ROOT)).CreateSleepThresholdAttr(0.0)
```

- 접촉 힘은 `create_rigid_contact_view` 로 만든 뷰의 `get_net_contact_forces(dt)` 로 읽음.
- 처음에는 값이 0 으로만 나왔음. 가만히 서 있는 로봇이 잠들어 있었기 때문임. `physxArticulation:sleepThreshold` 를 0 으로 두어 깨워 둠.
- 읽은 값의 합이 무게와 맞는지로 확인했음 (776.0 N, 894.2 N).

## 12. 정리

### 기억할 것

- 위치 구동만으로 무게를 버티면 팔이 처짐. 처짐은 버티는 힘 ÷ kp 쯤이고, 솔버 반복이 모자라면 더 큼.
- 중력 보상 = 지금 자세에서 드는 힘을 읽어 관절에 미리 더하는 것. 손의 처짐이 15.8 mm 에서 0.1 mm 가 됨.
- 바닥에 고정되지 않은 로봇은 값의 앞 6칸이 뿌리임. 관절 값은 그 뒤에 있음.
- 중력을 끄는 것은 보상이 아님. 팔의 무게 118 N 이 없어지고, 팔을 뻗어도 베이스가 모름.
- 가만히 서 있는 로봇은 잠듦. 접촉 힘을 재려면 깨워 둬야 함.

### 한계

- 보상은 모델의 질량으로 계산함. 손에 든 물체의 무게는 들어 있지 않음. 물체를 든 채의 처짐은 뒤 강의에서 봄.
- 중력을 끈 경우에도 0.1° 안팎의 오차가 남음. 반복 횟수를 늘리면 줄어드는 것은 보았지만 원인을 따로 가려내지는 않았음.
- 한 가지 속도(1.5초에 90°)로만 움직여 봤음. 더 빠른 동작에서 코리올리 항이 필요한지는 재지 않았음.
- 평평한 바닥에서, 물리 솔버 기본값(TGS) · 물리 주기 기본값(60 Hz)으로 잰 결과임. 실물 로봇의 값과 비교하지 않았음.
- 강의 PC 한 대(Isaac Sim 5.1)에서 확인한 결과임.
