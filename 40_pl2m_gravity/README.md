## 1. 강의 39 에서 미뤄 둔 것

### 이번 강의의 결과

- 왼팔에만 중력 보상을 넣고, 두 팔을 같은 자세로 움직임. 잘 보이도록 팔의 게인을 1/10 로 낮춘 시연임.
- 보상이 없는 오른팔은 13.5° 처지고, 보상을 넣은 왼팔은 0.4° 안에 있음.

### 강의 39 에서 한 것

- 강의 39 는 팔의 동작만 확인하려고 팔 링크의 중력을 꺼 두었음.
- 원본 MuJoCo 설정은 중력을 그대로 두고, 관절이 팔 무게만큼의 토크를 더 내게 함 (`bias_compensation: true`).
- 이번 강의는 중력을 다시 켜고, 수식으로 중력이 만드는 토크를 구한 다음, 한쪽 팔에만 보상을 넣어 다른 팔과 비교함.

### 세 가지 처리

- 구동만: 팔이 처져야 구동이 힘을 냄. 처짐이 남음.
- 구동 + 중력 보상: 필요한 힘을 미리 더함. 처지지 않고, 팔의 무게는 베이스에 그대로 실림.
- 팔 링크의 중력 끔: 처지지 않지만 팔의 무게가 없어짐. 바닥이 받치는 힘이 894 N 에서 776 N 으로 줄어듦.

### 다루는 순서

| 절 | 질문 |
|---|---|
| 2 · 3 | 중력이 관절에 만드는 토크는 얼마인가 (수식, 읽기) |
| 4 · 5 | 구동만으로는 왜 처지고, 보상은 어떻게 넣나 (수식, 코드) |

| 10 ~ 12 | 베이스에 실리는 무게, 움직이는 동안, 약한 팔 시연 |

## 2. 수식: 중력이 관절에 만드는 토크

### 링크 하나

- 무게 m·g 가 무게중심에서 아래로 당김. 관절이 버텨야 하는 토크는 무게 × 관절에서 본 수평 거리임.
- 팔을 수평으로 뻗으면 가장 크고, 아래로 내리거나 위로 세우면 0 임.

### 링크 여러 개

- 관절 하나는 자기 뒤에 달린 링크를 모두 받침. 링크마다 무게 × 수평 거리를 구해 더함.
- 수평 거리는 관절 축에서 링크의 무게중심까지를, 축에 수직인 방향으로 잰 것임. 부호가 있음.
- 자세가 바뀌면 무게중심의 위치가 바뀌므로, 이 값은 자세의 함수임. 이것을 g(q) 라고 씀.

### 코드: 수식 그대로

```python
for name in after:
    index = names.index(name)
    center = world(stage, name).Transform(Gf.Vec3d(*[float(v) for v in centers[index][:3]]))
    arm = Gf.Dot(axis, Gf.Cross(center - point, up))          # 축에서 본 수평 거리 (부호 있음)
```

## 4. 수식: 구동만으로는 왜 처지나

### 위치 구동은 용수철

- 위치 구동이 내는 토크는 목표와의 차이에 비례함. 차이가 0 이면 토크도 0 임.
- 무게를 버티는 토크를 내려면 그만큼 처져 있어야 함. 처짐 = 중력 토크 ÷ kp.
- 앞으로 뻗은 자세의 1번 관절은 1.27° 로 어림됨. 6절에서 재 봄.

## 5. 수식과 코드: 중력 보상

### 구동에 g(q) 를 더함

- 처지기를 기다리지 않고, 2절에서 구한 g(q) 를 관절에 미리 더함.
- 운동 방정식의 중력 항이 지워짐. 구동은 무게를 버티지 않아도 되고, 멈추는 곳이 목표와 같아짐.
- 원본 MuJoCo 설정은 C 항까지 함께 넣음 (`qfrc_bias`). C 항은 움직일 때만 생김. 11절에서 재 봄.

### 코드: 물리 스텝마다 더하기

```python
def _on_step(self, dt):
    efforts = np.zeros((self.robot.count, self.robot.max_dofs), dtype=np.float32)
    if self.enabled:
        needed = self.robot.get_gravity_compensation_forces()
        if self.coriolis:                                     # 움직일 때 생기는 힘(코리올리 · 원심력)까지
            needed = needed + self.robot.get_coriolis_and_centrifugal_compensation_forces()
        efforts[:, self.dofs] = needed[:, self.shift + self.dofs]
    self.robot.set_dof_actuation_forces(efforts, self._every)
```

- g(q) 는 자세의 함수이므로 물리 스텝마다 다시 읽어 넣음.
- `set_dof_actuation_forces` 로 넣는 토크는 위치 구동이 내는 토크와 따로이고, 둘이 더해짐. 수식의 τ 가 됨.
- `joints` 로 정한 관절에만 넣음. 기본은 팔 관절 14개임. 원본도 손가락을 뺀 팔 관절에만 보상함.

### 코드: 스텝마다 부르게 하기

```python
self.enabled, self.coriolis = True, coriolis
self._every = np.arange(self.robot.count)
self._sub = omni.physx.get_physx_interface().subscribe_physics_step_events(self._on_step)
```

- 물리 스텝마다 불리는 이벤트임. 강의 3 의 떨어지는 상자와 `common/sim.py` 의 `Sim` 이 쓰는 것과 같음.

### 쓰는 법


### 위치 비교

- 움직이는 동안의 오차는 두 팔이 비슷함. 차이는 멈춘 뒤에 남는 값임.
- 오른팔(구동만)은 1.66° 와 1.27° 에서 멈춤. 왼팔(보상)은 0.08° 와 0.06° 로 돌아옴.

### 토크 비교

- 멈춰 있을 때 버티는 토크는 두 팔이 같음 (11.08 N·m). 누가 내느냐가 다름.
- 오른팔은 구동이 11.08 N·m 를 냄. 그 토크를 내느라 1.66° 처져 있음.
- 왼팔은 보상이 11.08 N·m 를 내고, 구동이 낸 토크는 0.00 N·m 임. 구동은 움직일 때만 일함.

### 읽기

- 4절의 어림값은 1.27° 였고 잰 값은 1.66° 임. 더 처지는 이유는 8절에서 봄.
- 구동이 낸 토크는 관절이 받치는 전체 토크에서 보상으로 넣은 토크를 빼서 구했음. `get_dof_projected_joint_forces()` 와 `get_dof_actuation_forces()` 임.
- 한 로봇 안에서 한 번에 잰 비교임. 베이스의 움직임, 물리 설정이 두 팔에 똑같이 들어감.

- 게인을 4배로 올리면 1.3 ~ 4.7 mm 로 줄지만 0 이 되지는 않음. 처짐 = 중력 토크 ÷ kp 이기 때문임.
- 보상을 넣으면 0.1 mm 이하임.

### 게인만 올리는 방법

- kp 를 4배(2000)로 올리면 처짐이 1/3 ~ 1/5 로 줄어듦. 없어지지는 않음.
- kv 도 2배(70)로 같이 올렸음. 게인을 어디까지 올릴 수 있는지, 올리면 무엇이 나빠지는지는 재지 않았음.

```python
@staticmethod
def prepare(stage):
    for link in GROUND_LINKS:                                 # 접촉을 보고하게 한다
```

## 15. 정리

### 기억할 것

- 중력이 관절에 만드는 토크 = 뒤에 달린 링크마다 무게 × 수평 거리를 더한 것. 자세의 함수 g(q) 임.
- 위치 구동만으로 버티면 중력 토크 ÷ kp 만큼 처짐. 솔버 반복이 모자라면 더 처짐.
- 중력 보상 = 구동에 g(q) 를 더하는 것. 버티는 토크는 그대로이고, 구동 대신 보상이 냄. 손의 처짐이 15.8 mm 에서 0.1 mm 가 됨.
- 바닥에 고정되지 않은 로봇은 값의 앞 6칸이 뿌리임. 관절 값은 그 뒤에 있음.
- 중력을 끄는 것은 보상이 아님. 팔의 무게 118 N 이 없어지고, 팔을 뻗어도 베이스가 모름.

### 한계

- 보상은 모델의 질량으로 계산함. 손에 든 물체의 무게는 들어 있지 않음. 물체를 든 채의 처짐은 뒤 강의에서 봄.
- 중력을 끈 경우에도 0.1° 안팎의 오차가 남음. 반복 횟수를 늘리면 줄어드는 것은 보았지만 원인을 따로 가려내지는 않았음.
- 한 가지 속도(1.5초에 90°)로만 움직여 봤음. 더 빠른 동작에서 C 항이 필요한지는 재지 않았음.
- 평평한 바닥에서, 물리 솔버 기본값(TGS) · 물리 주기 기본값(60 Hz)으로 잰 결과임. 실물 로봇의 값과 비교하지 않았음.
- 강의 PC 한 대(Isaac Sim 5.1)에서 확인한 결과임.
