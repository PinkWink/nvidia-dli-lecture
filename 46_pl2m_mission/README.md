## 1. 세 가지를 잇기

### 이번 강의의 결과

- PL-2M 이 음료대로 가서 노란 컵을 오른팔로 집고, 상담 테이블로 가져가 내려놓은 뒤 처음 자리로 돌아옴. 3분쯤 걸림.
- 화면 위의 글자가 그때의 모드임.
- 처음 만든 임무는 왼팔로 분홍 컵만 됐고, 든 컵이 손 안에서 기울 때가 있었음. 까닭을 찾아 고친 과정이 6 ~ 7절과 9절임.

### 지금까지 만든 것

| 강의 | 만든 것 | 이 강의에서의 모드 |
|---|---|---|
| 43 | 서 있는 로봇이 컵을 집음 | ARM |
| 44 | Nav2 로 스테이션 앞까지 감 | NAV2 |
| 45 | 마커를 보고 테이블에 정확히 섬 | SETTLE ~ UNDOCK |

- 셋은 따로는 다 됨. 이번 강의는 이것을 하나의 임무로 이음.
- 잇는 일의 대부분은 모드가 바뀌는 자리에서 생김. 무엇을 확인하고 넘어가는가, 무엇을 건네는가.

### 모드의 순서

- 강의 45 의 그림에 ARM 모드가 하나 더 들어감. DOCKED 다음에 팔이 일하고, 그것이 끝나야 물러남.
- 임무 한 번에 이 고리를 두 번 돎. 음료대에서 한 번(집기), 상담 테이블에서 한 번(놓기).

### 모드 사이에 건네는 것

| 넘어가는 곳 | 확인하는 것 | 건네는 것 |
|---|---|---|
| NAV2 → 도킹 | Nav2 가 끝났나, 베이스가 멈췄나 | 없음. 도킹은 마커를 처음부터 다시 잼 |
| 도킹 → ARM | 베이스가 멈췄나 | 선 자리: 마커 면까지 0.43 m, side, turn |
| ARM 하는 동안 | 베이스가 제자리인가 (오도메트리로 5 mm · 0.5°) | 건네받은 값을 계속 씀 |
| ARM → UNDOCK | 팔이 운반 자세인가 | 없음 |
| UNDOCK → NAV2 | 0.75 m 물러났나 | 없음. Nav2 는 지도에서 자기 위치를 다시 봄 |

- 값을 건네는 곳은 한 군데뿐임. 도킹이 팔에게 건네는 선 자리.
- 나머지는 앞 모드의 결과를 믿지 않고 새로 잼. 그래서 앞 모드의 오차가 뒤로 쌓이지 않음.

## 4. 도킹 → 팔: 건네받은 값으로 자리를 셈함

### 수식

- 팔은 컵이 로봇의 어디에 있는지를 알아야 함. 컵이 부스의 어디에 있는지는 미리 알고, 로봇이 테이블 앞 어디에 섰는지는 도킹이 알려 줌.
- side 와 turn(t) 이 강의 45 의 도킹이 건넨 값임. 둘 다 0 이면 로봇이 축 위에 반듯이 선 것임.

### 코드

```python
def to_base(station, point, side=0.0, turn=0.0):
    x0, y0, yaw = docked_pose(station)
    dx, dy = point[0] - x0, point[1] - y0
    ahead = dx * math.cos(yaw) + dy * math.sin(yaw)                  # 축을 따라 앞으로
    left = -dx * math.sin(yaw) + dy * math.cos(yaw) + side           # 축에서 왼쪽으로 + 로봇이 축에서 벗어난 만큼
    return ahead * math.cos(turn) - left * math.sin(turn), ahead * math.sin(turn) + left * math.cos(turn), point[2]
```

- 부스 좌표의 점을, 도킹한 로봇 기준의 (앞, 왼쪽, 높이)로 바꿈. 컵 · 놓을 자리 · 가구에 모두 이 함수를 씀.
- 높이는 그대로 씀. 로봇의 기준(`base_footprint`)이 바닥에 있고, 부스 좌표도 바닥이 높이 0 임.

### 코드: 가구와 사람을 MoveIt 에 알림

```python
def add_furniture(self, station, where, more=()):
    items = []
    for name, kind, center, size in FURNITURE[station] + ([] if self.ignore_people else people_near(station)):
        turned = kind == "box" and abs(math.sin(STATIONS[station]["goal"][2])) > 0.7       # 로봇이 ±y 쪽을 보면 상자의 가로세로가 바뀐다
        items.append(shape(name, kind, to_base(station, center, *where), (size[1], size[0], size[2]) if turned else size, yaw=where[1]))
    self.arm.apply(world=items + list(more))
```

- 강의 42 에서 장애물을 알린 것과 같음. 다른 점은 자리를 `base_footprint` 기준으로 준다는 것임.
- ARM 모드에 들어올 때 넣고, 나갈 때 뺌. 로봇이 다른 테이블로 가면 그 자리에는 그 가구가 없기 때문임.
- 가구뿐 아니라 가까이 선 사람 모형도 넣음. 처음에는 넣지 않았고, 그래서 오른팔이 실패했음 (6절).

- 음료대 앞에 Nav2 로 도착한 뒤, 마커를 보지 않고 오도메트리로 0.585 m 만 나아가 집어 본 것임.
- 선 자리가 좌우 8.2 cm, 방향 6.5° 어긋나 있었음. 팔은 그것을 모르고 컵이 정해진 자리에 있다고 보고 손을 뻗었음.
- 손가락은 빈 곳에서 13.9 mm 까지 닫혔음. 컵은 6 mm 밀렸을 뿐 그 자리에 있음. 도킹이 건네는 값이 없으면 팔이 일할 수 없음.

## 5. 팔: 집기와 놓기

### 끝에서부터 거꾸로 확인함

```python
way_back = [(back, y, lift), (x, y, lift), (x, y, tip_z), (x + GRASP["pre_offset_x"], y, tip_z)]
fraction, joint_names, path = self.plan_line(side, way_back, start=self.joints(side, "carry"))
if fraction < 0.999:
    raise ArmError(f"집기 전 확인: 운반 자세에서 컵까지 직선으로 이어지지 않음 ...")
self.arm_to_joints(side, dict(zip(joint_names, path[-1])))
```

- 팔을 움직이기 전에, 집은 뒤의 길을 거꾸로 계획해 봄. 운반 자세의 팔 모양에서 출발해 뒤쪽 위 → 컵 위 → 컵 → 접근 시작 자리까지 직선으로.
- 다 이어지면 그 끝의 팔 모양(관절 7개의 각도)을 접근 시작 자세로 씀. 거기서 출발하면 집은 뒤 같은 길로 운반 자세까지 돌아올 수 있음.
- 강의 43 은 접근 시작 자리를 손끝 자세로만 주었음. 팔 모양은 MoveIt 이 그때그때 골랐고, 집은 뒤 운반 자세로 가는 길이 이어질지는 가 봐야 알았음.

### 코드: 직선을 계획만 함

```python
request.start_state.is_diff = True
if start:
    request.start_state.joint_state.name, request.start_state.joint_state.position = list(start), [float(v) for v in start.values()]
request.waypoints, request.max_step, request.avoid_collisions = [pose_at(*point) for point in points], 0.01, avoid
answer = self.arm.call(self.arm.cartesian, request)
```

- 강의 43 의 직선 경로(`/compute_cartesian_path`)와 같은 서비스임. 다른 점은 둘임.
- `start_state` 에 관절 각도를 넣으면 "팔이 그 모양일 때" 를 셈함. 팔을 그리로 보내지 않고도 물어볼 수 있음.
- 받은 궤적을 실행하지 않음. `fraction` 과 궤적의 마지막 점(그 끝의 팔 모양)만 씀.

### 코드: 집어서 운반 자세로

```python
self.straight(side, x, y, tip_z, "접근")
position, _, _ = self.arm.grip(side, GRASP["close"])
self.arm.tell_payload(side, CUP_MASS)
self.arm.attach(side, cup)
self.straight(side, x, y, lift, "들기")
self.straight(side, back, y, lift, "뒤로 빼기")
self.straight(side, *carry, "운반 자리로 당기기")
self.arm_to(side, "carry")
```

- 확인해 둔 길을 그대로 감. 접근해서 쥐고, 4 cm 들고, 뒤로 빼고, 몸 쪽으로 당겨 운반 자세(carry)가 됨 (일부만 보였음).
- 모두 직선이라 손의 방향이 그대로고 컵이 서 있음. 운반 자리에 왔을 때 팔 모양은 운반 자세와 2° 안에서 같았음. 마지막 줄은 그 차이를 맞추는 작은 움직임임.
- 손에 든 무게 0.2 kg 은 쥔 직후에 로봇에 알림 (강의 43).

### 직선이 끊기면 까닭을 물어봄

```python
cut, _, _ = self.plan_line(side, points, start)
free, names, path = self.plan_line(side, points, start, avoid=False)
if free < 0.9:
    at_limit = [name[-6:] for name, value in zip(names, path[-1]) if min(value - LIMITS[name][0], LIMITS[name][1] - value) < 0.03]
    return "관절 한계: " + ", ".join(at_limit) if at_limit else "팔이 닿지 않음"
request.robot_state.joint_state.position = path[min(len(path) - 1, int(cut * len(path)) + 1)]
contacts = self.arm.call(self.validity, request).contacts
```

- `fraction` 은 "몇 % 에서 끊겼다" 만 알려 줌. 왜 끊겼는지는 두 번 더 물어 알아냄.
- 충돌 검사를 끄고 다시 계획함. 그래도 끊기면 관절이 더 못 가는 것임. 마지막 점에서 한계에 닿은 관절을 찾음.
- 끝까지 가면 부딪혀서 끊긴 것임. 끊긴 자리의 다음 점을 `/check_state_validity` 에 물으면 무엇과 무엇이 부딪히는지 알려 줌.

### 코드: 놓기

```python
self.arm_to(side, "carry")
back = max(x + GRASP["retreat_x"], CARRY_TIP[0] + 0.03)
self.straight(side, back, y, tip_z + GRASP["lift_z"], "놓을 자리의 뒤로")
self.straight(side, x, y, tip_z + GRASP["lift_z"], "놓을 자리 위로")
self.lower(side, x, y, tip_z)
self.arm.grip(side, GRASP["open"])
```

- 집을 때와 같은 길임. 운반 자리 → 놓을 자리의 뒤쪽 위 → 놓을 자리 위 → 아래. 모두 직선이라 컵이 서 있음.
- 컵 바닥이 상판 4 mm 위에 왔을 때 그리퍼를 엶. 그 뒤 MoveIt 에 컵이 손에서 떨어졌다고 알리고, 로봇에 알린 무게를 0 으로 되돌림.
- 내리는 구간(`lower`)만은 MoveIt 의 충돌 검사를 끔. 컵이 상판에 닿으러 가는 길이라, 켜 둔 채로는 마지막 1 cm 에서 끊길 때가 있었음 (아홉 번에 두 번).

### 놓을 자리를 원본과 다르게 정한 까닭

| 놓을 자리 (가장자리에서 · 축에서 옆으로) | 접근 시작 자세의 수 | 놓기까지 직선이 되는 것 | 운반 자세에서 직선으로 |
|---|---|---|---|
| 5.5 cm · 0 cm (원본의 첫 자리) | 0 | 0 | 6 % |
| 5.5 cm · 10 cm (원본의 둘째 자리) | 1 | 1 | 100 % |
| 5.5 cm · 15 cm | 7 | 7 | 100 % |
| 9 cm · 5 cm | 6 | 6 | 11 % |
| 9 cm · 10 cm | 7 | 7 | 100 % |
| **9 cm · 15 cm (이 강의)** | 12 | 12 | 100 % |

- 상담 테이블 1 에 도킹한 자리에서, 왼팔로 놓을 자리마다 MoveIt 에 물어본 결과임 (팔은 움직이지 않음). 오른팔도 되는 자리와 안 되는 자리가 같았음.
- 둘째 열은 그 자리의 12 cm 뒤 손끝 자세에 대해 찾은 서로 다른 팔 모양의 수임. 원본의 첫 자리에는 하나도 없었고 둘째 자리에는 하나뿐이었음. 찾는 수는 물을 때마다 조금씩 다름. 축에 가까운 자리일수록 줄어듦.
- 그래서 든 팔의 정면, 가장자리에서 9 cm 안쪽 · 축에서 15 cm 옆으로 정했음. 옆으로 10 cm 까지는 되므로 도킹 오차 2 cm 에 여유가 있음.

## 6. 팔이 닿는 범위

### 컵의 자리마다 닿는 팔이 다름

- 도킹한 자리에서 컵의 옆 자리를 1 cm 씩 바꿔 가며 MoveIt 에 물어본 결과임 (팔은 움직이지 않음). 5절의 "거꾸로 확인" 을 자리마다 한 것임.
- 진한 칸에서만 집어서 운반 자세까지 직선으로 갈 수 있음. 컵이 로봇의 가운데에서 그 팔 쪽으로 3 cm 넘게 떨어져 있으면 늘 됨.
- 분홍 컵(+15 cm)과 노란 컵(-15 cm)은 진한 칸에 있음. 가운데의 파란 컵은 진한 칸과 옅은 칸이 섞인 곳(±2 cm)에 있음.

### 가운데 컵은 1 cm 차이로 되다 안 되다 함

```text
y -0.03   왼팔: 해  2 접근  73% 거꾸로  24%    오른팔: 해  5 접근 100% 거꾸로 100%
y -0.02   왼팔: 해  3 접근  80% 거꾸로  65%    오른팔: 해  5 접근 100% 거꾸로   9%
y -0.01   왼팔: 해  3 접근  91% 거꾸로  70%    오른팔: 해  3 접근 100% 거꾸로 100%
y +0.00   왼팔: 해  4 접근 100% 거꾸로 100%    오른팔: 해  3 접근 100% 거꾸로 100%
y +0.01   왼팔: 해  3 접근 100% 거꾸로 100%    오른팔: 해  4 접근  90% 거꾸로  70%
y +0.02   왼팔: 해  4 접근 100% 거꾸로   9%    오른팔: 해  3 접근  82% 거꾸로  65%
y +0.03   왼팔: 해  4 접근 100% 거꾸로 100%    오른팔: 해  2 접근  73% 거꾸로   5%
```

- 위 그림의 가운데 부분임. y 는 컵이 로봇의 왼쪽으로 떨어진 거리 [m], "거꾸로" 는 운반 자세에서부터 거꾸로 직선이 이어진 비율임.
- 컵이 정확히 가운데(0 cm)에 있으면 됨. 2 cm 만 벗어나면 9 % 에서 끊김. 도킹은 옆으로 2 cm 까지 벗어나 설 수 있으므로, 가운데에 서서 집는 것은 될 때도 있고 안 될 때도 있음.
- 끊기는 자리에서는 어깨의 관절 1 · 2 가 한계에 닿음 (5절의 방법으로 물어본 것). 몸 한가운데로 손을 곧게 뻗는 자세가 관절 범위의 끝에 있음.

### 코드: 비켜 서서 집음

```python
def arm_and_aim(station, cup):
    left = to_base(station, CUPS[cup])[1]                             # 축 위에 섰을 때 컵이 로봇의 왼쪽으로 떨어진 거리
    if abs(left) >= REACH:
        return ("left" if left > 0 else "right"), 0.0
    people = [to_base(station, center)[1] for _, _, center, _ in people_near(station)]
    step_left = not people or min(people, key=abs) < 0               # 가장 가까운 사람이 오른쪽에 있으면 왼쪽으로 비켜 선다
    return ("right", -REACH - left) if step_left else ("left", REACH - left)
```

- 팔이 닿는 것이 확실하지 않으면 베이스가 설 자리를 바꿈. 컵이 그 팔 쪽으로 12 cm 떨어지게 옆으로 비켜 서서 도킹함 (`REACH`, 늘 되는 3 cm 에 도킹 오차와 넉넉한 여유를 더한 값).
- 비켜 서는 쪽은 가까운 사람이 없는 쪽임. 음료대에서는 오른쪽 0.53 m 에 사람이 서 있어 왼쪽으로 비켜 서고, 오른팔로 집음.
- 돌려준 값을 강의 45 의 도킹에 `aim` 으로 건넴. 모드 사이에 건네는 값이 하나 더 생긴 셈임. 팔이 베이스에게 설 자리를 알려 줌.

### 팔이 일할 자리는 2 cm 안에 섬

```python
ARM_TOLERANCE = 0.02
_, (_, *where) = base.go_and_dock(source, aim=aim, tolerance=ARM_TOLERANCE)
```

- 강의 45 의 도킹은 옆으로 5 cm 안이면 그대로 다가갔음. 남은 옆 거리는 건네는 값으로 알려 주면 된다고 보았음.
- 팔이 닿는 범위에는 그만한 여유가 없었음. 놓을 자리(옆으로 15 cm)는 10 cm 까지만 닿아서, 로봇이 3.4 cm 비켜 서자 내리는 직선이 75 % 에서 끊겼음.
- 그래서 팔이 일할 자리에서는 2 cm 를 넘으면 옆걸음을 함. 옆걸음 한 번에 15 ~ 17초가 걸림.

### 로봇이 돌면 컵의 자리가 틀어짐


- 같은 실행의 터미널 6 임. 계획으로는 다 이어졌는데, 팔이 가는 동안 베이스가 0.7° 돌았음.

- 도킹이 건넨 값은 로봇이 그 자리에 그대로 서 있을 때만 맞음. 그 전제가 깨졌으므로 집지 않고 멈춤.

### 사람은 원본에서 부딪히지 않는 도형이었음

```xml

```

- 원본 MuJoCo 장면의 사람은 `contype="0"` 임. 라이다에는 보이지만 무엇과도 부딪히지 않음. 원본에서는 팔이 사람을 지나가도 아무 일이 없음.
- Isaac Sim 의 PhysX 라이다는 충돌체만 봄. 그래서 강의 38 에서 사람에게도 충돌체를 붙였고, 그 뒤로 사람은 부딪히는 물체가 됐음.
- MoveIt 은 알려 준 것만 피함. 가구는 알렸지만 사람은 알리지 않았음. 장면을 옮기며 바꾼 것 하나가 세 강의 뒤에 팔의 실패로 나타난 것임.

### 코드: 가까이 선 사람을 읽어 옴

```python
        ...
```

- 도킹한 자리에서 1 m 안에 선 사람 모형의 도형을, 시뮬레이터가 읽는 것과 같은 장면 파일에서 읽음 (`people_near`, 일부만 보였음).
- 다리 · 몸통 · 팔(캡슐)은 원기둥으로, 머리는 공으로 옮기고 2 cm 씩 키움. 음료대에서는 두 사람의 도형 14개가 들어감. 상담 테이블에는 1 m 안에 사람이 없음.
- 사람 하나를 반지름 26 cm 의 원기둥 하나로 넣어 봤을 때는 운반 자세의 팔꿈치가 그 원기둥과 겹쳐 계획이 세 번 모두 실패했음. 도형 그대로 넣어야 했음.

- 왼팔로 분홍 컵을 집을 때는 사람을 알리지 않아도 닿지 않았음. 그래서 처음에는 왼팔만 되는 것으로 보였음.

### 가구를 딱 맞게 알리면 상판을 스침

```text
   20.0초  팔이 닿음: openarm_right_left_finger ↔ Parts/drink_stand_top_182 (9.4 N·s)   로봇의 방향 89.7°
   20.5초  팔이 닿음: openarm_right_left_finger ↔ Parts/drink_stand_top_182 (15.8 N·s)   로봇의 방향 89.2°
[   23.3초] ARM    → FAILED (실패)  접근 시작 자리에서: 팔이 움직이는 동안 베이스가 3.7 mm · 1.6° 움직였음. 도킹이 건넨 값을 쓸 수 없음
```

- 음료대를 제 크기 그대로 알렸을 때의 기록임. 오른팔이 접근 시작 자리로 가다가 손가락이 음료대의 상판을 스쳤고, 베이스가 1.6° 돌았음.
- MoveIt 은 닿지만 않으면 되는 길을 냄. 시뮬레이터의 팔은 그 길을 몇 mm 벗어나 따라감. 여유가 0 인 길은 닿음.
- 그래서 팔이 접근 시작 자리로 가는 동안에는 가구를 사방으로 1 cm 키워 겹쳐 알림 (`add_guard`). 그 뒤 임무 여섯 번에서 팔이 닿은 기록은 없었음.

### 코드: 키운 가구는 가는 동안에만

```python
guard = self.add_guard(station, where)                 # 가구를 1 cm 키운 것을 겹쳐 넣는다
self.arm_to_joints(side, dict(zip(joint_names, path[-1])))
self.remove(guard)
```

- 키운 가구를 계속 두면 안 됨. 컵은 상판 위에 놓여 있어서, 쥔 컵이 키운 상판과 처음부터 겹침. 그렇게 두었을 때는 드는 직선이 0 % 에서 끊겼음.
- 컵으로 다가가고 · 쥐고 · 드는 직선 구간은 5절에서 미리 확인한 길임. 그 구간은 제 크기의 가구로 계획함.

## 8. 팔과 베이스: 한 번에 한쪽만

### 코드: 팔이 움직이는 동안 베이스가 제자리인지 봄

```python
def check_base(self, when):
    self.base.spin(0.2)
    x, y, yaw = self.base.odom()
    moved, turned = math.hypot(x - self.stood[0], y - self.stood[1]), abs(dock.angle_difference(yaw, self.stood[2]))
    if moved > BASE_STILL[0] or turned > BASE_STILL[1]:
        raise ArmError(f"{when}: 팔이 움직이는 동안 베이스가 {moved * 1000:.1f} mm · {math.degrees(turned):.1f}° 움직였음. 도킹이 건넨 값을 쓸 수 없음")
```

- ARM 모드에 들어올 때 오도메트리를 적어 두고(`mark_base`), 접근 시작 자리에 왔을 때 · 집은 뒤 · 내려놓기 전에 다시 봄.
- 5 mm 나 0.5° 넘게 달라졌으면 멈춤. 7절의 실패가 이 확인에 걸린 것임. 이 확인이 없던 때에는 까닭 없이 "직선이 50 % 에서 끊김" 으로만 보였음.
- 참값이 아니라 오도메트리를 봄. 실제 로봇에서도 쓸 수 있는 확인임. 바퀴가 돌지 않고 미끄러지기만 하면 잡지 못함.

### 코드: 자세를 확인하고 떠남

```python
def leave(self, side, pose):
    """도킹한 자리를 떠난다. 팔이 정해진 자세가 아니면 베이스를 움직이지 않는다."""
    if not self.arm_at(side, pose):
        raise ArmError(f"{side} 팔이 {pose} 자세가 아님: 베이스를 움직이지 않음")
    self.base.undock()
```

- 팔이 테이블 위로 뻗은 채로 베이스가 물러나면 팔이 테이블을 치거나 컵을 끎. 그래서 떠나기 전에 팔의 관절 각도가 운반 자세(놓은 뒤에는 이동 자세)인지 확인함.
- 반대쪽도 같음. 팔을 움직이기 전에 베이스가 멈춘 것을 확인함. 강의 45 의 도킹이 끝날 때 이미 확인돼 있음.

### 한 번에 한쪽만

| 모드 | 베이스 | 팔 |
|---|---|---|
| NAV2 · 도킹 | 움직임 | 이동 자세나 운반 자세로 고정 |
| ARM | 서 있음 (움직였는지 확인함) | 움직임 |

- Nav2 의 발자국(앞뒤 ±0.38 m · 좌우 ±0.32 m)은 팔이 접혀 있을 때의 크기임. 팔을 뻗은 채 다니면 Nav2 가 모르는 부분이 생김.
- MoveIt 에 알린 가구와 사람의 자리는 로봇이 서 있을 때만 맞음. 팔이 움직이는 동안 베이스가 밀리면 그만큼 틀어짐.

## 11. 정리

### 기억할 것

- 임무는 모드를 이은 것임. NAV2 로 가고, 도킹으로 서고, ARM 으로 일하고, 물러나서 다시 NAV2.
- 도킹이 팔에게 선 자리(거리 · side · turn)를 건넴. 팔은 그것으로 컵과 놓을 자리를 로봇 기준으로 셈함. 거꾸로 팔은 베이스에게 설 자리(비켜 설 거리)를 알려 줌.
- 한 번에 한쪽만 움직임. 넘겨주기 전에 확인함: 베이스가 멈췄는가, 팔이 접혔는가, Nav2 가 끝났는가. 팔이 일하는 동안에도 베이스가 제자리인지 봄.
- 팔을 움직이기 전에 끝에서부터 거꾸로 확인함. 직선이 끊기면 무엇과 부딪히는지, 어느 관절이 한계인지를 물어봄.
- MoveIt 은 알려 준 것만 피함. 시뮬레이터에서 부딪히는 것은 모두 알려야 함. 사람 모형을 빠뜨린 것이 오른팔 실패의 원인이었음.
- 물체를 쥐는 면이 한 점이면 물체가 손 안에서 돎. 손가락 안쪽에 평평한 패드를 덧대 두 점으로 누르게 했음.
- 컵 셋을 두 테이블로 나르는 임무가 여섯 번 모두 됐음. Nav2 는 2 ~ 20 cm 벗어나 섰고, 컵은 목표에서 4 mm 안에 놓였음.

### 한계

- 손가락의 패드는 딱딱한 상자임. 실제 패드처럼 눌리지 않음. 컵보다 무겁거나 모양이 다른 물체는 쥐어 보지 않았음.
- MoveIt 에 알리는 가구의 여유 1 cm 는 팔이 상판을 스친 뒤에 넣은 값임. 팔이 계획한 길에서 얼마나 벗어나는지를 재서 정한 값이 아님.
- 컵과 놓을 자리는 미리 정해진 자리임. 카메라로 컵을 찾지 않았고, 놓을 자리가 비어 있는지도 보지 않았음.
- 사람 모형의 자리는 장면 파일에서 읽었음. 실제 로봇이라면 라이다나 카메라로 알아내야 함. 그것은 하지 않았음.
- 놓는 자리와 길은 원본과 다르게 정했음. 원본의 자리에는 팔이 닿지 않았음 (5절).
- 실패했을 때의 뒷정리가 모자람. 팔 작업이 실패하면 그 자리에서 멈춤. 든 컵을 내려놓고 물러나는 것까지는 만들지 않았음.
- 사람 모형은 움직이지 않음. 가는 길에 사람이 들어서는 경우는 보지 않았음.
- 임무는 컵마다 2번, 모두 여섯 번을 해 본 것임. 실패가 얼마나 잦은지 말하기에는 적은 횟수임.
- 강의 PC 한 대(Isaac Sim 5.1, ROS 2 Jazzy, Nav2, MoveIt 2)에서 확인한 결과임.
