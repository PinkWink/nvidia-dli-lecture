# 33. 핑크랩 로터리 역진자 2: 지연 · 마찰 · 센서 잡음을 넣고 다시 학습 — 명령 모음

영상에서 입력하는 터미널 명령과 기대 출력을 순서대로 모았습니다. [32. 핑크랩 로터리 역진자](../32_pinklab_pendulum/README.md) 다음 내용입니다.


## 1. 시뮬레이션과 실물의 차이

### 강의 32 의 시뮬레이션

- 명령은 보낸 순간 팔에 닿았습니다.
- 정책은 팔과 진자의 정확한 각도와 속도를 받았습니다.
- 4,096대의 진자가 모두 똑같은 마찰을 가졌습니다.

### 실물 장치

| 실물에 있는 것 | 내용 |
|---|---|
| 지연 | 명령이 통신과 모터를 거쳐 팔에 닿기까지 수십 ms |
| 진자 각도 센서 | 12비트. 한 바퀴를 4,096칸으로 나눈 눈금(0.088°)과 잡음 |
| 진자 속도 | 속도 센서가 없음. 각도의 차이를 시간으로 나눠 계산 |
| 팔 각도 | 팔을 재지 않음. 모터에 보낸 스텝 수(한 바퀴 1,600스텝)를 셈 |
| 마찰 | 장치마다, 날마다 다름 |

- 눈금과 스텝 수, 그리고 지연이 수십 ms 라는 것은 장치를 만든 팀의 인수인계 자료에 적힌 내용입니다. 이 강의에서 실물로 재지는 않았습니다.

### 이 강의의 순서

- ① 강의 32 의 정책을 불완전한 조건에서 평가합니다.
- ② 불완전함을 넣은 채로 다시 학습합니다.
- ③ 두 정책을 같은 조건에서 비교합니다.

## 2. 환경에 넣은 세 가지

`32_pinklab_pendulum/pendulum_env.py` 에 설정 세 개가 있습니다. 강의 32 에서는 모두 꺼져 있었습니다.

### 설정

```python
delay_range = (0.0, 0.0)      # 명령이 팔에 닿기까지의 지연 [s]
friction_range = (1.0, 1.0)   # 진자 마찰에 곱하는 배율
sensor_noise = False          # 센서의 눈금 · 잡음, 각도의 차이로 구한 속도
```

- 범위로 준 값은 에피소드를 시작할 때 **환경마다 하나씩** 뽑습니다.

### 지연

```python
self.accel_history = torch.roll(self.accel_history, 1, dims=1)
self.accel_history[:, 0] = self.action * MAX_ACCEL
accel = self.accel_history[self.rows, self.delay_steps]
```

- 최근의 명령 32개를 기억해 둡니다. 물리 한 번(1/700초)마다 한 칸씩 뒤로 밉니다.
- 팔에는 지금 명령이 아니라 `delay_steps` 칸 전의 명령을 줍니다. 28칸이 40 ms 입니다.

### 마찰

```python
friction = self.friction_scale * (-VISCOUS * speed - COULOMB * torch.tanh(speed / 0.05))
```

- 강의 32 의 마찰 식에 환경마다 다른 배율을 곱합니다.

### 센서: 진자

```python
theta = torch.round(theta / ENCODER_STEP) * ENCODER_STEP + ENCODER_NOISE * torch.randn_like(theta)
difference = theta - self.measured_angle
difference = torch.atan2(torch.sin(difference), torch.cos(difference))
pendulum_speed = difference / self.step_dt
```

- 각도를 눈금에 맞춰 반올림하고 잡음(0.002 rad)을 더합니다.
- 속도는 "이번 각도 − 지난번 각도"를 제어 주기로 나눈 값입니다. 각도의 잡음이 속도에서는 더 크게 나타납니다.

### 센서: 팔

```python
arm_angle = torch.floor(self.arm_angle_command / MOTOR_STEP) * MOTOR_STEP
arm_speed = self.arm_speed_command
```

- 실제 팔의 각도 대신, 모터에 보낸 명령을 쌓아 센 각도를 줍니다.

### 보상은 그대로

- 보상은 시뮬레이터의 정확한 값으로 계산합니다. 바뀌는 것은 **정책이 보는 것**과 **팔이 움직이는 때**입니다.

## 3. 강의 32 의 정책을 시험

### 지연 40 ms 와 센서 잡음을 넣고 평가

```bash
cd ~/nvidia-dli-lecture
~/IsaacLab/isaaclab.sh -p 32_pinklab_pendulum/play.py --headless --num_envs 256 --seconds 8 --delay 40 --sensor_noise --checkpoint work/pendulum_logs/내폴더/model_599.pt
```

- `--checkpoint` 에 강의 32 에서 학습한 정책을 넣습니다.
- `--delay` 는 ms, `--friction` 은 배율입니다.

### 결과

```text
256대를 매달린 자세에서 8초 동안 돌렸습니다. (지연 40 ms, 마찰 1.0배, 센서 잡음 있음)
  선 진자: 0대 (0 %)
  끝날 때 서 있는 진자: 9대
  팔이 가장 멀리 간 각도: 평균 108°, 최대 117°
```

- 한 대도 세우지 못합니다. 지연이 없을 때는 256대를 모두 세운 정책입니다.

### 조건을 하나씩 바꿔 보면

|---|---|---|
| 아무것도 넣지 않음 | 256대 | 1.43초 |

### 무엇이 약점인가

- **지연**입니다. 20 ms 에서 두 배 느려지고, 40 ms 에서 무너집니다.
- 마찰이 절반이거나 1.5배여도 모두 세웁니다. 센서 잡음만으로도 무너지지 않습니다.
- 정책은 "명령이 바로 닿는다"를 전제로 배웠습니다. 늦게 닿으면 세우는 순간의 미세한 조정이 엇박자가 됩니다.

## 4. 불완전함을 넣고 다시 학습

### 도메인 랜덤화

- 강의 27 에서는 영상의 조명과 물체 자리를 장마다 바꿨습니다. 모델이 한 가지 조건을 외우지 않게 하려는 것이었습니다.
- 여기서는 **물리 값**을 환경마다 바꿉니다. 정책이 한 가지 지연, 한 가지 마찰을 외우지 않게 합니다.

### 학습 명령

```bash
~/IsaacLab/isaaclab.sh -p 32_pinklab_pendulum/train.py --headless --realistic --max_iterations 2000
```

- `--realistic` 은 지연 0 ~ 40 ms, 마찰 0.5 ~ 1.5배, 센서 잡음을 켭니다.
- 결과 폴더 이름 끝에 `_realistic` 이 붙습니다.

### 걸린 시간

```text
              Mean episode upright: 0.9227
학습 시간: 1631초
```

- 강의 PC 에서 2,000번에 27분 11초입니다. 학습 도중에 다른 Isaac Sim 창을 몇 분 띄웠으므로, 단독으로 돌리면 이보다 조금 짧을 것입니다.

### 학습 곡선

- 강의 32 는 250번쯤에 0.9 를 넘었습니다. 여기서는 600번이 걸립니다. 더 어려운 문제입니다.
- **1,000번 근처에서 크게 무너졌다가** 다시 올라옵니다. 학습이 늘 좋아지기만 하는 것은 아닙니다.

### 600번으로는 부족했다

- 처음에는 강의 32 처럼 600번만 학습했습니다. 세운 정도가 0.77 에서 끝났고, 지연 40 ms 에서 256대 중 3대만 세웠습니다.
- 같은 명령을 2,000번으로 다시 돌린 것이 위의 곡선입니다. 이 학습에서는 500번째 정책이 이미 256대를 세웠습니다.
- 학습은 실행할 때마다 결과가 다릅니다. 이 환경은 무작위 씨앗을 고정하지 않습니다.

## 6. 두 정책의 비교

### 같은 조건에서

| 조건 | 강의 32 의 정책 | 이 강의의 `model_800` |
|---|---|---|
| 아무것도 넣지 않음 | 256대, 1.43초 | 256대, 2.12초 |
| 지연 20 ms + 센서 잡음 | 173대, 4.45초 | 256대, 1.76초 |
| 지연 40 ms + 센서 잡음 | 0대 | 256대, 1.88초 |

- 불완전함이 없을 때는 강의 32 의 정책이 더 빠릅니다(1.43초 대 2.12초). 그 조건만 보고 배웠기 때문입니다.
- 지연이 생기면 뒤집힙니다. 여러 조건을 겪으며 배운 정책은 어느 조건에서도 무너지지 않습니다.

### 지연 40 ms 에서의 8초

- 왼쪽(강의 32 의 정책): 진자가 꼭대기 근처까지 가지만 붙잡지 못하고 계속 돕니다.
- 오른쪽(`model_800`): 2.5초에 세우고, ±5° 안에서 흔들리며 버팁니다.
- 오른쪽의 팔은 가운데가 아니라 −50° 근처에 머뭅니다. 강의 32 에서도 본 모습입니다.

## 7. 한계

### 이 강의에서 하지 않은 것

- **실물 장치에서 시험하지 않았습니다.** 여기까지는 모두 시뮬레이션 안의 비교입니다.
- 팔이 한계에 닿는 문제를 풀지 않았습니다. 팔이 가운데를 벗어난 벌점을 키우는 옵션(`--arm_center_weight`, 기본 0.02)을 넣어 두었지만, 다른 값으로 학습해 보지는 않았습니다.
- 학습은 한 번(2,000번)의 결과입니다. 다시 돌리면 무너지는 때와 좋은 정책의 번호가 달라질 수 있습니다.

### 전시에 쓴 정책과의 차이

- 전시에 쓴 정책은 더 많은 것을 무작위로 주었습니다. 인수인계 자료에는 팔이 명령을 늦게 따라가는 정도, 센서의 치우침, 중력의 크기까지 범위로 준 것으로 적혀 있습니다.
- 학습도 여러 단계에 걸쳐 수천 번을 했습니다. 이 강의의 환경은 그중 세 가지만 옮긴 것입니다.

## 8. 정리

### 이 강의에서 본 것

- 이상적인 시뮬레이션에서 배운 정책은 지연 40 ms 에서 한 대도 세우지 못했습니다.
- 지연 · 마찰 · 센서 잡음을 환경마다 다르게 주며 배운 정책은 같은 조건에서 256대를 모두 세웠습니다.

### 기억할 것

- **도메인 랜덤화**: 실물에서 달라질 수 있는 값을 범위로 주고 배웁니다.
- 더 어려운 문제라 학습이 길어지고, 도중에 무너지기도 합니다.
- **마지막 정책이 가장 좋은 것은 아닙니다.** 여러 개를 저장하고, 여러 조건에서 평가해 고릅니다.
- "세웠다"만 보지 않습니다. 팔이 한계에 닿는지처럼, 실물에서 문제가 될 동작도 함께 봅니다.
